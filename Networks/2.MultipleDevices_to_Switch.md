## **2. Multiple Devices -> Switch**
### **Devices**
- 2 PCs
- 2 Laptops
- 1 Switch (2960)

### **Connection**
- PC0 Fa0 -> Switch0 Fa0/1
- Laptop0 Fa0 -> Switch0 Fa0/2
- PC1 Fa0 -> Switch0 Fa0/3
- Laptop1 Fa0 -> Switch0 Fa0/4
- Use Copper Straight-Through cables.

### **PC configuration**
- PC0 -> `192.168.1.10`
- Laptop0 -> `192.168.1.11`
- PC1 -> `192.168.1.12`
- Laptop1 -> `192.168.1.13`
- Subnet Mask -> `255.255.255.0`

### **Test**
- Check PC/laptop configuration: `ipconfig`
- Check switch ports: `show interfaces status` (Show physical connections are established)
- Check MAC addresses learned by switch: `show mac address-table`
- PC0 -> Laptop0: `ping 192.168.1.11`
- PC0 -> PC1: `ping 192.168.1.12`
- PC0 -> Laptop1: `ping 192.168.1.13`

- Before generating traffic, the switch has not learned the MAC addresses of the devices.

- Switch learns only the source MAC address of each incoming frame and maps it to the port where the frame arrived.
- If the destination MAC address is unknown, the switch broadcasts the frame out the other ports.
- The intended device receives the frame and sends a reply.
- When PC1 -> PC3 communicate, the switch learns the source MAC address of each device from their incoming frames and maps each MAC address to
  its corresponding port.
- <img width="600" alt="image" src="https://github.com/user-attachments/assets/372e6b18-95e3-4e70-ae5b-fead82dd1e54" />
- <img width="600" alt="image" src="https://github.com/user-attachments/assets/5c992dcb-6d48-4fac-822c-aa0a39d2fe78" />
- Dynamic MAC entries are removed after the MAC address aging time if no new frames are received from that source.

### **Failure Cases**
- IP address already in use -> In the real world, assigning the same IP address to two devices causes an IP conflict and communication confusion;
  in Packet Tracer, it shows that the IP address is already in use in the network.
- <img width="600" alt="image" src="https://github.com/user-attachments/assets/f19f6470-a630-4301-abf6-320f9e9ca14b" />
- Different subnet -> Even if the IP subnet is different, the device can still receive the Ethernet frame because the switch forwards it
  using the destination MAC address; therefore, ping can work in this switch-only Packet Tracer setup.
- <img width="600" alt="image" src="https://github.com/user-attachments/assets/7547f8bc-067b-4b54-bfb2-6820172b675f" />

### **Troubleshooting**
- Check the IP address of all devices
- Check that all devices are in the same subnet
- Check the switch MAC address table

### **Result**
- All four devices communicate through the same switch.
- The switch learns the MAC address of each connected device.
