## 4. Inter-VLAN Routing

### **Problem**
- We now have two separate VLANs:
  - VLAN 10 -> Students
  - VLAN 20 -> Staff
- Devices in the same VLAN can communicate with each other.
- Devices in different VLANs cannot communicate directly through a Layer-2 switch.
- A trunk can carry VLAN 10 and VLAN 20 traffic, but it does not allow the two VLANs to communicate with each other.

### **Solution**
- To allow devices in different VLANs to communicate, we need a router or Layer-3 switch.
- This process is called Inter-VLAN Routing.

### Commands used
**Configure the switch-to-router link as a trunk:**
- enable 
- configure terminal 
- interface gigabitEthernet 0/1 
- switchport mode trunk 
- exit

**Configure the router's physical interface:**
- enable
- configure terminal
- interface gigabitEthernet 0/0
- no shutdown

**Configure the VLAN 10 subinterface:**
- interface gigabitEthernet 0/0.10
- encapsulation dot1Q 10
- ip address 192.168.1.1 255.255.255.0

**Configure the VLAN 20 subinterface:**
- interface gigabitEthernet 0/0.20
- encapsulation dot1Q 20
- ip address 192.168.2.1 255.255.255.0

**Configure the default gateway on the end devices:**
- VLAN 10 -> `192.168.1.1`
- VLAN 20 -> `192.168.2.1`

### Troubleshooting
- Check VLANs and access-port assignments: show vlan brief
- Check the switch-to-router trunk: show interfaces trunk
- Check router interfaces and subinterfaces: show ip interface brief
- Test connectivity between devices: ping <IP-address>

### Result
- VLAN 10 and VLAN 20 were successfully connected through Router0 using Inter-VLAN Routing.
- The switch-to-router link carries both VLANs as a trunk.
- Router subinterfaces identify VLAN 10 and VLAN 20 and act as their default gateways.
- Devices in different VLANs can now communicate through the router using IP addresses.
